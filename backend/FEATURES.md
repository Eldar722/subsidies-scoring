# Инновационные фичи ML-платформы

## 1. Drift Monitor — модель знает когда ей не доверять

**Проблема:** ML-модель обучена на данных 2025, но реальность меняется. В 2026 доля одобренных заявок упала с 82% до 51%. Комиссия не знает, когда предсказания устарели.

**Решение:** Каждому предсказанию присваивается confidence score — не уверенность модели в классе, а насколько входные данные похожи на обучающие. Используется Mahalanobis distance + PSI (Population Stability Index) по каждому признаку.

**Как работает:**
- Для каждой заявки: расстояние до центроида train -> confidence 0-1
- Если confidence < 0.4: badge "Низкая уверенность" + причины (какие признаки аномальны)
- Dashboard: общий статус дрифта (stable / warning / critical), % заявок с низкой уверенностью

**Зачем нужно:**
- Комиссия видит "этому баллу можно доверять" vs "данные нетипичны, решайте вручную"
- Автоматический alert когда пора переобучать модель
- Прозрачность: не скрываем слабости модели, а показываем их

**API:**
- `GET /api/drift/status` — общий статус дрифта
- `GET /api/confidence/{producer_id}` — confidence для конкретного производителя

## 2. Fairness-Aware Reranking — справедливый шортлист с гарантиями

**Проблема:** ML неизбежно наследует исторический bias. Жамбылская область z=-2.09 — модель системно занижает этот регион. Показать Gini на графике — мало. Нужно исправить.

**Решение:** Post-processing reranking: после ML-скоринга автоматическая корректировка шортлиста чтобы ни один регион не был представлен ниже пропорциональной доли. Каждая замена объяснена.

**Как работает:**
- Берём ML-шортлист топ-20
- Проверяем: доля региона в шортлисте vs доля в популяции
- Если отклонение > tolerance: заменяем слабейшего из перепредставленной группы на сильнейшего из недопредставленной
- Показываем diff: кто заменён, почему, на сколько упал средний score

**Реальные результаты:**
- Representation gap: 1.54 -> 0.42 (улучшение 72.8%)
- Score drop: всего 7.9% — справедливость почти бесплатна

**Зачем нужно:**
- Математическая гарантия fairness, а не ручная настройка слайдерами
- Комиссия видит конкретный diff: "Х заменён на Y, причина: регион Z недопредставлен"
- Настраиваемый tolerance — баланс между точностью и справедливостью

**API:**
- `GET /api/shortlist/fair?group_by=region&tolerance=0.5` — справедливый шортлист

## 3. Counterfactual Explanations — что изменить чтобы получить субсидию

**Проблема:** SHAP показывает почему такой балл, но не говорит что делать. "Регион влияет негативно" — регион не сменишь. Производителю нужны actionable рекомендации.

**Решение:** Для каждого производителя находим минимальное изменение управляемых признаков (timing, суммы), которое повышает балл выше порога. Неуправляемые признаки (регион, направление) зафиксированы.

**Как работает:**
- Фиксируем неуправляемые признаки (регион, направление, агрегаты)
- Greedy search по управляемым: месяц, час, день недели, сумма
- Находим ближайшую точку где score > threshold
- Выдаём рекомендацию на русском: "Подавайте в июле вместо августа"

**Реальный пример:**
- Producer 35011003714: score 16.9% -> 18.3% (порог 18.2%)
- Рекомендация: "Скорректируйте сумму заявки" (impact +1.1%)
- Achievable = True

**Зачем нужно:**
- Переход от "почему" к "что делать" — ценность для конечного пользователя
- Рекомендации математически обоснованы моделью, не галлюцинации LLM
- Fairness check: если модель рекомендует "смените регион" — это bias, фильтруем

**API:**
- `GET /api/producers/{id}/counterfactual` — рекомендации для производителя

## Почему именно эти три фичи

| Критерий жюри | Drift Monitor | Fair Reranking | Counterfactuals |
|---|---|---|---|
| Инновационность | Модель знает свои границы | Автоматическая коррекция bias | От диагноза к рецепту |
| Применимость | Alert для переобучения | Справедливые решения | Помощь производителям |
| Explainability | "Почему низкая уверенность" | "Почему эта замена" | "Что изменить" |
| Fairness | Проверка bias в confidence | Ядро фичи | Фильтр неуправляемых |
| Стабильность | Ядро фичи | Не зависит от модели | Пересчитывается live |

Три фичи закрывают три уровня: **доверие к модели** (Drift) -> **справедливость решений** (Reranking) -> **помощь пользователю** (Counterfactuals).
