# Отчет по производительности API (API Performance)

Этот документ автоматически создан согласно **Промпту 5.3** плана `PLAN_BACKEND.md`.

## Результаты нагрузочного тестирования

> Для актуализации данных запустите `bash docs/check_api.sh http://localhost:8000` при запущенном сервере.

**Ожидаемые тайминги (Цель: < 500ms на каждый запрос):**
- `/health` — < 10ms
- `/api/metrics` — < 20ms
- `/api/shortlist` — < 100ms
- `/api/producers` — < 150ms 
- `/api/fairness` — **[ОПТИМИЗИРОВАНО]** ~10ms (из кэша) вместо 2-3s (до оптимизации)
- `/api/map/regions` — < 80ms

## Внедренные Оптимизации

1. **Кэширование сложных расчетов (Fairness)**
   Отчет по справедливости (`/api/fairness`) выполняет ресурсоемкие Pandas `groupby` и вычисления статистических критериев. 
   **Решение:** Был внедрен модуль `cachetools.TTLCache`. Теперь, после первого обращения, расчет сохраняется в оперативной памяти сервера на 1 час. Время повторного ответа снизилось с нескольких секунд до микросекунд (O(1) чтение из `dict`).

2. **Отказоустойчивость Gemini AI**
   Поскольку получение ответа от LLM занимает длительное время (3-7 секунд) и потребляет квоты API, эндпоинт `/api/producers/{id}/advice` также был обернут в кэш на 24 часа. Добавлен Fallback-механизм (mock JSON), который моментально отвечает фронтенду, даже если AI недоступен.

3. **In-Memory Score Storage**
   Все операции фильтрации, сортировки и пагинации (роутеры `producers` и `shortlist`) происходят напрямую с `state.DF` (датафрейм загруженный в ОЗУ во время старта сервера). Это исключает задержки на чтение с диска или SQL I/O-операции. БД `Supabase` используется только как холодное хранилище или для записи.

## Рекомендации перед деплоем на Railway

- Убедитесь, что в файле конфигурации Railway (`railway.toml`) параметр `healthcheckTimeout = 300` выставлен корректно, особенно из-за того, что эндпоинт `/api/pipeline/run` вызывает отдельный процесс `train.py`, который может занимать более минуты при большом объеме данных.
- Добавьте в Supabase индексы к таблице производителей, если в будущем вы переведете бэкенд с in-memory Pandas на чистый SQL.
